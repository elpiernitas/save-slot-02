# SAVE SLOT 02 — Content Backlog

Planning only. No item here is automatically approved for implementation.

## GAME-05 — inventory + original cards

Goal: reward exploration without turning the game into a collectible grind.

### Inventory philosophy

Maximum useful categories:
- QUEST;
- OBJECT;
- CONSUMABLE (mostly jokes / flavour);
- KEY.

Keep the first release small: roughly 6–10 meaningful entries.

Candidate objects:
- `TICKET STUB` — generic cinema ticket, not tied to a copyrighted film;
- `SIDRA CRATE` — absurdly heavy "provisions";
- `MYSTERY RECEIPT` — unreadable supply receipt;
- `EMPTY GLASS` — somehow marked as quest-relevant;
- `COAST TOKEN` — found near the promenade;
- `PLAYER 2 SLOT` — initially blank/system item, later changes state.

### Cards

Original card system inspired by the pleasure of collecting physical cards,
not Pokémon mechanics/art.

Working concept: **CITY CARDS**.

A card can represent:
- place;
- object;
- NPC;
- event;
- absurd status.

Rarity should be playful, not monetised.

Potential first cards:
- LA MURALLA — PLACE;
- BOLLARD Lv. ??? — OBJECT;
- SEAGULL WITH INTENT — NPC;
- EMPTY TABLE — PLACE;
- AFTERNOON IN CIMAVILLA — EVENT.

Cards can include:
- small pixel illustration;
- one-line flavour;
- discovery timestamp;
- optional "found by class" variation.

No booster packs, gacha or store.

## GAME-06 — puzzle seeds

Keep puzzles short. Luis plays many games; avoid tutorialising obvious
controls.

Candidates:
- **two-state street puzzle**: change a mundane city object's state in the
  correct order;
- **inventory logic**: combine/inspect two ordinary objects;
- **route puzzle**: choose a path through a compressed Gijón node using
  environmental clues;
- **NPC sequence**: three short conversations reveal the next location;
- **class alternate**: class changes one solution or line, never blocks
  progress.

Avoid:
- trivia about the relationship;
- "what is Manu's favourite X?" quizzes;
- password puzzles based on private information;
- long sliding-block filler.

## GAME-07 — boss + PLAYER 2

Boss should be game-y rather than emotionally symbolic.

Potential tone:
- corrupted quest process;
- absurd bureaucratic system entity;
- city-navigation anomaly;
- "pending player" error taking physical form.

Mechanics can use:
- dodge;
- pattern recognition;
- class-specific minor advantage;
- dialogue interruptions.

After boss:
`PLAYER SLOT 02 — SIGNAL FOUND`

Then Manu appears.

## GAME-08 — date portals

Visual metaphors:
- three lit save portals;
- station-style departure board;
- calendar gates;
- three city exits.

Do not make the user answer a form.

Each option should show enough information to choose:
- WED 30 SEP;
- THU 01 OCT;
- SUN 04 OCT.

Friday:
- visible but locked;
- `MAIN QUEST ACTIVE`;
- theatre 18:30 can appear as the reason after the reveal.

## GAME-09 — ending states

Ending must:
- write chosen date;
- persist after refresh;
- show save confirmation;
- provide a satisfying 15–30 second final beat;
- make returning to the site worthwhile.

No confetti-web aesthetic.

## GAME-10 — post-game

Possible later unlocks:
- chosen-date countdown;
- one small new interaction;
- card gallery;
- "mission complete" state after date;
- optional message after the real-world plan.

Do not require a backend unless a real use case appears.

## GAME-11 — OST direction

No commercial tracks.

Reference energy from shared playlist:
- urban / latin;
- indie;
- rock in Spanish;
- salsa / merengue;
- 80s/90s/2000s;
- modern alternative electronics.

Leitmotif concept:
a simple 4–6 note motif transformed per district:
- warm guitar/pluck during day;
- synth at sunset;
- bass/percussion at night;
- stripped-down version at ending.
